End-to-End Data Pipeline

Raw YouTube audio → structured intelligence, across 7 pipeline stages

STAGE 1
📥
EXTRACT
yt-dlp + YouTube Data API v3
  • 25 curated channels
  • 6 genres (AI, Health, VC, Business, Science, Society)
  • WebVTT auto-captions download
  • Metadata: title, date, guests, description, tags
  • ~90% transcript accuracy
286 episodes · 25 channels
STAGE 2
📦
LOAD
snowflake_loader.py
  • PUT → Snowflake internal stage
  • COPY INTO RAW.EPISODES
  • VARIANT column (full JSON)
  • Key-pair auth (no password)
  • ~50ms per episode
RAW.EPISODES · 286 VARIANT rows
STAGE 3
🔧
TRANSFORM
Snowflake SQL Views
  • STG_EPISODES: VARIANT → 22 typed cols
  • STG_SEGMENTS: LATERAL FLATTEN → 1 row/cue
  • INT_EPISODES: + quality + engagement rate
  • INT_SEGMENTS: + YouTube timestamp URL
  • Views = zero storage cost
4 SQL views (zero storage cost)
STAGE 4
✂️
CHUNK
CUR_CHUNKS · Snowflake SQL
  • 120-second sliding windows
  • 15-second overlap (context continuity)
  • Deep-link per chunk: youtube.com/watch?v=ID&t=SEC
  • Word count + quality score per chunk
  • ~48 chunks per episode avg
13,807 chunks · 100% with embeddings
STAGE 5
🧠
ENRICH
Snowflake Cortex · llama3.1-70b
  • Arctic-embed-m → 768-dim vectors
  • Topic extraction (2–5 per chunk)
  • Named entity recognition (people, orgs)
  • Structured claim extraction + speaker attribution
  • Temporal evolution detection + drift scoring
84,260 claims · 823 evolution pairs
STAGE 6
🔍
INDEX
Cortex Search + Neo4j
  • PODCASTIQ_SEARCH: hybrid BM25 + vector
  • Auto re-ranking via Cortex cross-encoder
  • Neo4j: 88,823 nodes, 253,740 edges
  • Node types: Person, Episode, Topic, Claim, Channel
  • Cypher queries for graph traversal
Cortex Search + Neo4j live
STAGE 7
🖥️
SERVE
LangGraph + Streamlit
  • Router → 8 specialized agents
  • Input guardrails (length, injection, scope, language)
  • Chat interface with source cards
  • Graph Explorer (pyvis force-directed)
  • Channel Dashboard + real-person disclaimer
3 UI pages · 9 agents · <5s p95

DIAGRAM 7

Neo4j Knowledge Graph Schema

88,823 nodes and 253,740 relationships enabling GraphRAG — relationship reasoning beyond what vector search can provide

🔵 Node Types

Person

name, type (HOST/GUEST/EXPERT). Entity-resolved to merge duplicate name variants.

Episode

video_id, title, channel, publish_date. Links hosts → guests → topics → claims.

Claim

claim_text, claim_type, date, speaker. Includes EVOLVED_FROM edges for temporal linking.

Topic

name (e.g. "AI Safety", "Longevity"). Connected to episodes + persons via DISCUSSED edges.

Channel

name, genre. Hub node — every episode and host belongs to exactly one channel.

Organization

name (e.g. "OpenAI", "Anthropic"). Linked to persons via AFFILIATED_WITH.

🔗 Edge Types (253,740 total)

APPEARED_ON

Person → Episode. role: HOST or GUEST

CO_APPEARED_WITH

Person ↔ Person. count + episodes[] array. Bidirectional.

MADE_CLAIM

Person → Claim. attribution_confidence score

DISCUSSED

Episode → Topic. frequency count

EVOLVED_FROM

Claim → Claim. drift_type + time_delta_days

AFFILIATED_WITH

Person → Organization

⌨️ Example Cypher Queries
// Guest network query
MATCH (p:Person {name: 'Sam Altman'})
      -[r:CO_APPEARED_WITH]->(co:Person)
RETURN co.name, r.count
ORDER BY r.count DESC LIMIT 10
// Temporal contradiction query
MATCH (c1:Claim)-[e:EVOLVED_FROM]->(c2:Claim)
WHERE e.drift_type = 'CONTRADICTED'
   AND c1.speaker = 'Marc Andreessen'
RETURN c1.claim_text, c2.claim_text,
        e.time_delta_days
ORDER BY e.time_delta_days
